# Security model

Trust boundaries and accepted risks. Each item names the decision that enforces it. A change that moves a boundary updates this file in the same change.

- **Peers are untrusted for integrity** (*withhold, never forge*):
  - blobs are checked against their digest, and a peer that sends a wrong one is skipped locally for a while; no node can evict another cluster-wide (D7, D52);
  - on the fetch path a peer can only withhold: on containerd the agent sends the runtime nothing of a peer's blob or manifest until the whole has matched its digest; on CRI-O it holds back the last chunk, so a wrong blob fails that pull, which kubelet retries without the peers that sent it. A peer that is slow, busy, stalled or gone costs time: the fetcher hedges, moves on, resumes with `Range` from the next, and falls through to upstream when none is left. The fetcher dials only the node a lookup named and requires that node's certificate (D16, D52, D67, D73, D102);
  - artifacts are checked against their digest and signature (D8);
- **Peers choose what a tag names (accepted).** With `mirror.resolve_tags` on, the default, a tag resolves to the manifest the first of 2 holders sends (D123). The mirror hashes it itself, so the runtime gets that manifest and only content that matches it, but any node with a node identity can name any manifest of 4 MiB at most for any tag, and a disagreement only logs a warning. A moved tag keeps resolving to the old image while peers hold it. M5's signature check rejects an unsigned image, not an older signed one. `mirror.resolve_tags = false` gives tags back to upstream, live.
  - TUF metadata authenticates itself, so it can travel P2P (D26).
- **Peers are authenticated for identity.** Only holders of a kubelet client certificate from the cluster CA can talk to the peer API or a reflector, and a node can only announce content for itself (D16).
  - **What a node claims:** its name, the `<name>` of `CN=system:node:<name>` under `O=system:nodes`, in a certificate that chains to the cluster CA, carries `clientAuth` and is valid now. Both sides of a link check the same, and a client also checks that the server is the node it dialled (D16, D95).
  - **What it cannot claim:** another node's name, without that node's key or the cluster CA's; any other subject, such as the apiserver's kubelet client certificate (no `O`) or an admin's (`O=system:masters`); a certificate of another cluster. Whoever holds the cluster CA's key, or can make the CSR signer issue for a node name, can be any node.
  - **Where it lives:** the key is read from kubelet's file into memory, and a handshake reads no file. A file whose key does not match its certificate, or whose subject is not a node's, is refused and the pair in use stays (D95).
- **A reflector trusts each node for its own announcements, and bounds them.** It takes a stream's node from the TLS peer's certificate and refuses a `Hello` naming another. It believes what a node says it holds: a lying node can only waste its peers' fetch attempts, since every blob is checked (D7). It holds at most 100k digests for one node, a frame at most 4 MiB, refused from its length before any of it is buffered, a handshake at most 5 s and a silence at most 40 s; a peer address must be an IP literal, so a node cannot send fetchers to a name. Each refusal is counted (D97, D105).
- **An agent trusts the reflector list only from a listed reflector.** It reaches `reflector.url` through a load balancer that is not trusted, so a `Members` answer counts only when the node of the certificate that answered is in the list it returns; any other keeps the previous list. Each member is then dialled at its listed address and must prove that node (D16, D98).
- **An agent announces only its runtime's `k8s.io` content, or its blob cache.** Content of containerd's other namespaces never reaches a reflector (D99).
- **Lookups tell every node what every other holds (accepted).** Any node can ask any digest and learn up to 8 nodes holding it, with their peer addresses. Which images run where is visible to every node, as to Spegel's DHT (D2, D97).
- **The local mirror is closed to other local processes.** The runtime authenticates with a root-only client certificate, so `hostNetwork` pods cannot read cached layers through it. It listens on loopback only; startup refuses any other `mirror.address` (D14, D56). `configure` writes the keys by temporary file and rename at mode 0600, tightening a looser file, and drops the CA's key once it has signed the two certificates, so no key can issue another client certificate (D55, D82).
- **Pod pull secrets never reach the agent.** On CRI-O the mirror never answers 401, because CRI-O would then send it the pull's credentials, which belong to the upstream registry. It resolves tags with the node's own credentials at upstream, after the peers that hold the tag (D66, D123).
- **On CRI-O the agent is in every pull's path.** CRI-O takes an image whole from the mirror once it serves the manifest, so the agent relays what it fetches from upstream; when the agent is down, CRI-O pulls from upstream (D66). It keeps a blob in its *blob cache*, and so serves it to peers, only once its digest matches; it holds back the last chunk until then, so CRI-O never receives a whole wrong blob (D67).
- **Discovery uses the node's registry credentials on both runtimes.** On containerd too, the agent now reads the logins, CAs and client certificates of containerd's registry config, and sends them to the endpoints that config names for each listed image, never to the node's own mirror (D17, D121). They are held and sent as the relay's are, below.
- **Stored artifacts are untrusted until M5 verifies them.** The *artifact store* keeps only blobs that match their digest (D7), and a referrer only when its manifest names its target as `subject`; nothing on the node acts on them yet, and the peer API serves them as they are (D124). Any upstream that serves a listed image can make each node keep, per target, at most 64 referrers of blobs up to `sbom.max_size` each (D121), kept while the image is listed (D131).
- **Artifacts and their referrers lists come from peers.** Discovery asks the store, then peers, then upstream only when peers give nothing (D126). Checked now: every manifest and blob matches its digest, in flight, and a peer that sends wrong bytes is denied (D52, D102); a bundle counts only when its manifest names the target as `subject`. Not yet checked, until M5: signatures. A peer can withhold an artifact by leaving it off its list, and can list any simple-signing manifest as a target's `.sig`, which names no subject; M5 binds the `.sig` to the target (D8) and asks upstream once before a final `Rejected`. Any node with a node identity can make another keep up to the same caps as an upstream can.
- **The relay holds the node's registry credentials, and sends them nowhere else.** They come only from the node's own registry config (D89); a login goes to its own endpoint's `host:port` and not to a redirect's, nor to a mirror's; tokens live in memory per host and scope; every one is a `SecretString` and no header is logged (D37, D88). A client certificate's private key is read at reload and held for the life of the registry config snapshot, as a `SecretString` that `Debug` does not print; the check that parses it makes a copy that is not wiped (D92). A credential, certificate or key file that cannot be used makes its hosts anonymous or without a client certificate, never wider trust (D92). The relay serves only the manifests it fetched for CRI-O and the blobs below them, so the mirror is no open proxy for those credentials (D88). The upstream client alone speaks TLS 1.2, for registries that speak nothing newer; the mirror's own listener stays on 1.3 (D85, D88).
- **Every node verifies for itself.** Verdicts are never shared, and a compromised control plane cannot relax a node's policy (D26).
- **Saved verdicts are as trusted as memory.** `/run/speculaire` is root-only and cleared at reboot. A file with an unknown version or a bad checksum is discarded, and entries saved under another policy or trust root only serve as stale verdicts (D31).
- **Secrets never reach a log.** Registry credentials and tokens are `SecretString`s, and HTTP tracing never records headers (D37).
- **The audit log names pods and images.** It is off by default and goes to the root-readable journal (D37).
- **A bad config never loosens the gate.** Unknown keys stop startup, and an invalid reload keeps the previous config (D30).
- **Private layers are shared, as in Spegel (accepted).** Any node of the cluster can fetch any cached layer without pull secrets. mTLS keeps non-nodes out, but any node can read another node's private layers.
- **The peer API serves any node any blob or manifest it can name (accepted).** It listens on the peer address, to any client with a kubelet certificate of the cluster CA (D16), and answers `GET` and `HEAD` by digest from what the node announces: containerd's `k8s.io` content or the blob cache (D99). A digest is the only key, so a node that learns one, from a reflector's `Lookup` or a manifest, reads that content without the image's pull secret. It serves a tag the runtime lists, as the manifest it holds for that image (D123), and no listing; `peer.max_uploads` bounds what one node can make it send at once (D24, D100).
- **The peer API serves the artifact store to any node (accepted).** To the same clients, it serves each artifact's manifest and blobs by digest, and, in any repository, the referrers of any manifest it holds artifacts about (D124): a node learns which signatures, attestations and SBOMs a node holds for an image, and their annotations, without its pull secret. The referrers index is a hint and not content-addressed: the node that serves it can list any manifest, so a reader fetches each by digest and checks its `subject`, as for any registry's. Those artifacts are as untrusted as the store that holds them, until M5 verifies them.
- **A joining node has no P2P.** Until its kubelet certificate exists, it pulls from upstream; the gate still enforces (D16).
- **The pause image is not gated.** NRI's `PodSandbox` carries no image.
- **On containerd 2.3, the identity check has a known gap (accepted).** A retag to an image with identical layers but a different config passes. The agent warns at startup; containerd 2.4 closes the gap (D15).
- **On CRI-O, the image identity is CRI-O's image ID.** CRI-O sets the annotations that carry it after the pod's own, so a pod cannot forge them. CRI-O passes no pod-spec image name, so every name of the image selects policies (D65).
- **Images that no policy matches** are denied by default; `gate.unmatched = "allow"` lets them through unchecked (D23).
- **Admins must allow-list the gate's own dependencies.** With `enforce` + `required_plugins`, a stopped agent blocks every container creation on the node, including control-plane static pods. `gate.exempt` (D18) and the NRI tolerate annotation are the escape hatches. Admins configure them before turning on `enforce` (`docs/operations.md`). `unconfigure` refuses to run while `required_plugins` names speculaire (D32).
- **The tolerate annotation is a pod annotation (accepted).** Anyone who can create a pod can set it, and that pod starts ungated whenever the agent is not registered with NRI (`containerd/nri` `pkg/plugin/annotations.go:40-59`). v1 ships no admission policy to restrict it. The DaemonSet's own pod carries it (D44).
- **Identity regexes match the whole SAN and issuer.** A `subjectRegExp` of `https://github.com/myorg/` does not pass `https://github.com/myorg-evil/…`, as it would in cosign and policy-controller; a pattern that does not parse alone refuses the policy (D136).
- **`.att` tags do not count.** Attestations are verified only as Sigstore bundles found as OCI referrers; `.att` and unsigned `.sbom` tags are ignored (D12, D43).
- **A BuildKit SBOM is trusted through the index signature.** It has no signature of its own; it counts only when the index digest that covers it has a passing signature (D12, D49).
- **Metrics are readable by anyone who can reach the node.** `/metrics` is plain HTTP on every address by default; it holds counts only, no secret and no pod or image label (D34, D42, D45, D50).
- **A gate timeout lets one container through (accepted).** NRI closes a plugin that misses `plugin_request_timeout` and starts that container ungated; D41 keeps the gate's answer under half the timeout and alerts on it.
- **The agent runs as root** with no capabilities, a read-only system and a syscall filter that denies io_uring (D4, D53).
- **The gate cannot be switched off.** No setting disables it, and a runtime with NRI disabled stops startup (D64); `audit` mode is the only way to admit everything, and it stays visible in metrics (D54).
