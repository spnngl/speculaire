# Checkers and crates: what speculaire adopts, when

Sources, read 2026-11-11: `~/src/github.com/BurtonQin/Awesome-Rust-Checker/README.md` (updated 2026-08-21), blessed.rs (`~/src/github.com/nicoburns/blessed-rs/data/crates.json`, commit of 2026-10-27), and dedens at `v0.1.0-131-gfd00747` (`docs/research/ci-dedens.md` § 4 lists its checks with file:line). The rows for nextest, Kani, Verus, Creusot, flux, Aeneas, Charon and MIRAI also read each one's repository under `~/src/github.com/`, at its newest tag. Every verdict is one of **adopt** (now), **trigger** (adopted when its named trigger lands; the milestone that lands it adds the check), **covered** (a tool already in place does the job) or **skip**.

The workspace denies `unsafe_code` and has no hand-written concurrent structure yet, so tools that look for memory errors or races find little today. They earn a place by being cheap to run outside `required`, or by arriving with their trigger.

## Testing and analysis tools

| Tool | Verdict | Why |
|---|---|---|
| cargo-mutants | adopt | The one tool that grades the tests themselves. dedens' shape: PR diff in up to 8 shards of 40, nextest, `--baseline=skip`, a stale-exclusion job (D142, D168 in dedens `docs/decisions/performance-and-safety.md`). The workspace lists 142 mutants (cargo-mutants 27.1.0, 2026-11-11), 19 of them in `e2e/src/lib.rs`. Run over the workspace with every package's tests, the 121 others take 13 minutes: 98 caught, 23 unviable, 2 changes excluded (D74). |
| cargo-nextest | adopt | cargo-mutants' test tool, as in dedens D103 (half the time of `cargo test` there), and since D72 the test runner of `just check` and `just cov` (cargo-nextest 0.9.151). `slow-timeout` with `terminate-after` ends a hung test with its name and kills its process group, `speculaire agent` children included, where `cargo test` waits for the job timeout. Leak detection fails a test whose child still holds the test's stdout or stderr; children with their own pipes, as in `apps/speculaire/tests/agent.rs`, escape it. The workspace has no doctest, and `just check` runs `cargo test --doc` for the first one. Speed is no argument: `just check` takes 14 s in CI. Not for `e2e/`: nextest runs test binaries in parallel, while the suites rely on `cargo test` running them one after another (`unit_reload.rs`, `unit_restart.rs`). `--stress-count` reruns one test to reproduce a flake. Archives would save each e2e leg only its test build, and a leg takes 60 s in all. |
| cargo-fuzz | covered | `fuzz/` and the nightly per-target matrix (`fuzz.yml`, dedens D141). Raw bytes stop at the first refused value: a second target writes config files from the keys, and finds in 10 s a panic after the parse that raw bytes miss in 300 s (D75). |
| cargo-careful | covered | Tests on a standard library with debug assertions, under AddressSanitizer, in one `deep` job (D76; dedens D144 has a job per package). glibc Linux only: macOS cannot link it and the musl build image has no ASan runtime. C dependencies (aws-lc-rs, mimalloc) are not instrumented. |
| RAPx | covered | On each pull request and weekly, outside `required`: use-after-free, double free and leaks (`check -f -m`) and optimization hints (`opt`). Builds on rustc internals at a pinned commit and nightly (dedens `justfile:3-9`, `rapx.yml`). `Box::into_raw` and `mem::forget` are safe, so leaks are reachable without `unsafe`. dedens' last six runs took 3 to 5 minutes. |
| cargo-llvm-cov | adopt | Line coverage feeds the ruleset's `code_coverage` rule (minimum 80 %, drop at most 2). GitHub Code Quality reads line coverage only, from a Cobertura XML report (`cargo llvm-cov --cobertura`) uploaded by `actions/upload-code-coverage` (v1.4.4, `2b21a77928be8d5168c2b9581a67f2adbebacc52`) with `code-quality: write`, on pushes to `main` (the baseline) and on pull requests. The rule does not wait for the upload, so the uploading job must be a required check. Local run, 2026-11-11, macOS, workspace without `e2e`: 87.5 % of lines, 85.2 % of regions. |
| Miri | trigger: the first `unsafe` | Interprets tests for UB; FFI (aws-lc-rs) and tokio I/O stop it, so only pure modules would run. |
| loom | trigger: the first hand-written concurrent structure on `std::sync` | Exhaustive interleavings; does not model tokio. |
| Shuttle | trigger: the NRI mux per-connection queues (M6) or the reflector streams (M3) | Randomized scheduling that runs async code, where loom does not. |
| lockbud | trigger: the first `std::sync::Mutex` held across calls | Static double-lock and lock-order detection; a pinned nightly like RAPx. |
| Kani | trigger: the NRI mux frame decoder (M6) | A bounded wire decoder (8-byte header, D9) is what Kani proves well (dedens D145). D27 dropped it for lack of such a decoder. It needs no annotation beyond a `#[kani::proof]` harness, and the code stays ordinary Rust. kani-0.68.0 (2026-09-15) pins `nightly-2026-08-21` and ships bundles for x86_64 and aarch64 Linux. It does not support `await` or concurrency (`docs/src/rust-feature-support.md`), so only synchronous, pure functions qualify. The config value parsers are string-shaped and already fuzzed, with `checked_mul` on sizes (`crates/agent/src/config/value.rs:164`); they are not worth a harness. |
| Valgrind (memcheck) | trigger: M3's load scenario | tokio runs its echo server under `valgrind --leak-check=full --error-exitcode=1` on each pull request (`.github/workflows/stress-test.yml` at `ab0814fc`), for its own `unsafe`. Here it would be the one runtime check that sees the C of aws-lc-rs, which cargo-careful's AddressSanitizer does not instrument. It runs only on the gnu host build: memcheck cannot replace `malloc` in a static binary, and the musl binary allocates through mimalloc (D46). Definite leaks only; a daemon's growing maps stay reachable, which M3's heap profiling (dhat) measures instead. Weekly in `deep`, with the agent serving the load scenario briefly, then SIGTERM. |
| KLEE | skip | Symbolic execution of LLVM bitcode, built for C with a uClibc POSIX model. KLEE 3.3 (2026-10-15) builds against LLVM 15 to 19, and rustc 1.99.1 emits LLVM 23 bitcode, which older LLVM cannot read. Kani covers bounded symbolic checking of Rust. |
| Tumult | skip | A chaos engineering platform (`mwigge/tumult` at `d2cd84e`, 2026-10-23): CLI, daemon, web UI and DuckDB journals over 912 crates, seven months old, one maintainer. Its Kubernetes faults run `tc netem` and stress-ng in ephemeral containers of a pod; the agent is a systemd unit on the node, out of their reach. The M3 faults need no platform: kind nodes ship iproute2 (kind `images/base/Dockerfile:77`), so the e2e suites run `tc qdisc add … netem` on a node through `docker exec`, and stop or kill the agent with `systemctl`. |
| tokio-netem | trigger: M3's peer client | The `AsyncRead`/`AsyncWrite` adapters under Tumult's TCP proxy (0.1.1, MIT, `brk0v/trixter`, one release in 2025-10): delay, throttle, corrupt, terminate a stream in-process. A unit test of a slow or truncated peer stream (D7) needs one such wrapper; adopt it, or write the ten lines it saves, when that test lands. |
| clippy `disallowed-methods`, `disallowed-types` | adopt with the first rule | D37's rules (credentials in `SecretString`, headers never logged) fit `clippy.toml`; dylint only for a rule clippy cannot express. |
| cargo-semver-checks | skip | `publish = false`: no crate has a public API to keep. |
| cargo-audit | covered | cargo-deny reads the same RustSec database (dedens D141 rejected it). |
| cargo-udeps | covered | cargo-shear in `just check`. |
| cargo-auditable | covered | `just musl` (D57). |
| cargo-vet | adopt | Each dependency is audited by a trusted party or exempted, and a new crate needs one or the other, inside `required`. cargo-vet 0.10.3 on `main` (2026-11-11): `cargo vet init` exempts 164 crates; importing the mozilla, google, bytecode-alliance, zcash, isrg and embark-studios sets (`registry.toml` in the cargo-vet repository) then `cargo vet prune` leaves 27 fully audited, 2 partially, 135 exempted; trusting the nine publishers those sets trust leaves 92 fully audited, 72 exempted (D71). `--locked` reads `imports.lock` and needs no network. `fuzz/` has its own `Cargo.lock`. |
| cargo-geiger, cargo-scan | skip | Report `unsafe` in dependencies without a decision to hang on the report. |
| MIRAI, Rudra, MirChecker, Yuga, redpen | skip | Unmaintained since 2024–2025 or pinned to old nightlies. MIRAI's last commit is v1.1.12 (2025-03-04), on `nightly-2025-01-10`, older than the workspace's `rust-version` 1.95. |
| Verus | skip | Verifies only code written inside its `verus!` macro, in its subset of Rust, against its own `vstd`. Rolling releases (0.2026.11.05) on Rust 1.99.1, the workspace's own pin. A proof would mean rewriting the module in that dialect. |
| Creusot | skip | Deductive verification through Why3 (v0.15.0, 2026-11-10, `nightly-2026-08-03`). It needs opam, Why3 and SMT solvers, a `creusot-std` dependency for the contracts, and specifications for every function it calls, which tokio, axum and serde do not have. |
| flux | skip | Refinement types checked by liquid-fixpoint and Z3 (`nightly-2026-10-22`). It has no published release and is built from source. It proves bounds and value ranges, which the workspace gets from `get(i)`, newtypes and `TryFrom`. |
| Aeneas, Charon | skip | Charon extracts a crate's MIR to JSON; it is a front end for other tools, not a checker. Aeneas turns that JSON into Lean, Coq, F\* or HOL4, where the proofs are written by hand (OCaml toolchain, nightly tags). |
| Prusti, hax | skip | Full verification: specifications cost more than the risk they remove here. |
| gh-actions-lock | trigger: its issue #179 fixed and Renovate able to refresh the lockfile, or 1.0 | A `gh` extension (`github/gh-actions-lock` v0.4.1, lockfile format v0.0.3) that writes `.github/workflows/actions.lock`: each action's commit, owner and repository IDs, and the actions a composite action calls. The runner checks the lockfile at job start when "Enforce workflow lockfiles" is on; the IDs refuse a commit from a fork or a re-created repository, which a SHA pin alone accepts. Tried on `main` at 2026-11-12: it rewrites the SHA pins of 7 workflows to tags, which fails zizmor's `unpinned-uses`, and it adds one composite dependency (`extractions/setup-crate`, which `setup-just` already pins by SHA). It cannot lock reusable workflows from another repository (#179), the four `spnngl/.github@main` ones being the only unpinned dependencies; and it knows only Dependabot, so each Renovate bump of an action would leave the lockfile stale. |
